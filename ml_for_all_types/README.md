# ml_for_all_types

Ансамбль лёгковесных ML-моделей-детекторов ПД. Для каждого типа ПД из реестра
`gliner_famous/model_interfaces/pii_types.py` создан отдельный подкаталог со
своей синтетикой, обученной моделью и тестом.

## Структура

```
ml_for_all_types/
├── _common.py        # общий ML-каркас (n-граммы + логистическая регрессия на numpy)
├── _synthetic.py     # генераторы синтетики для всех типов ПД
├── _train.py         # общий скрипт обучения
├── _test.py          # общий скрипт тестирования
├── ensemble.py       # СВОДНЫЙ ИНТЕРФЕЙС: ансамбль всех моделей
├── run_tests.py      # сводный прогон тестов
└── <CODE>/           # подкаталог каждого типа ПД
    ├── synthetic.py  # синтетика для типа
    ├── train.py      # обучение модели типа
    ├── test.py       # тест модели типа
    ├── model.npz     # веса (логистическая регрессия, ~4 КБ)
    └── meta.json     # метаданные модели
```

## Модель

Каждая модель — бинарный классификатор «содержит ли текст этот тип ПД»:
- **Признаки**: хэшированные символьные n-граммы (1..3) в вектор размерности 512.
- **Классификатор**: логистическая регрессия, обученная стохастическим
  градиентным спуском на чистом numpy.
- **Вес**: один `.npz` ~4 КБ на модель. Никаких тяжёлых зависимостей, кроме numpy.

## Использование ансамбля

```python
import ensemble

# Все типы с вероятностями (порог 0.5)
ensemble.detect("Иван Петров, паспорт 4510 123456, ИНН 770123456789")
# -> [{'code': 'PASSPORT', 'name': 'Серия и номер паспорта', 'score': 0.96}, ...]

# Только коды найденных типов
ensemble.detect_types("ivan.petrov@mail.ru, +7 (903) 123-45-67")
# -> ['EMAIL', 'PHONE']

# Детекция по окнам — выше полнота на длинных текстах
ensemble.detect_spans("Иван Петров, паспорт 4510 123456, ИНН 770123456789, ...")

# Вероятность конкретного типа
ensemble.score("паспорт 4510 123456", "PASSPORT")

# Перезагрузка после переобучения
ensemble.reload()
```

## Обучение / тест одного типа

```bash
.venv/bin/python PASSPORT/train.py   # обучить и сохранить модель PASSPORT
.venv/bin/python PASSPORT/test.py    # протестировать на свежей синтетике
```

## Сводный тест

```bash
.venv/bin/python run_tests.py
```

Прогоняет все 29 моделей на свежей синтетике (не использованной при обучении)
и проверяет ансамбль на реалистичных текстах.

## WS-сервис

По аналогии с `gliner_famous` оформлен FastAPI WebSocket-сервис
(`ws_server.py` + `Dockerfile` + `requirements.txt`). Эндпоинты:

- `POST /process` — JSON `{"text": "..."}` → найденные типы ПД;
- `WS /ws` — WebSocket-обработка текста.

Формат ответа аналогичен `gliner_famous`, но вместо сущностей возвращаются
типы ПД с вероятностью и позицией окна, где тип найден:

```json
{
  "work_time": 0.014,
  "length": 101,
  "count": 4,
  "data": [
    {"code": "INN", "name": "ИНН", "score": 0.9999, "slice": [30, 90]},
    {"code": "PASSPORT", "name": "Серия и номер паспорта", "score": 0.9958, "slice": [0, 60]}
  ]
}
```

Запуск локально:

```bash
.venv/bin/python -m uvicorn ws_server:app --host 127.0.0.1 --port 8001
```

Сборка и запуск в Docker:

```bash
docker build -t ml_for_all_types ./ml_for_all_types
docker run -d --name ml1 -p 8005:8000 ml_for_all_types
```

Проверка:

```bash
curl -X POST http://localhost:8005/process \
  -H "Content-Type: application/json" \
  -d '{"text": "Иван Петров, паспорт 4510 123456, ИНН 770123456789"}'
```

## Результаты

- Все 29 моделей: **F1 = 1.0** (точность/полнота/F1 = 1.0) на свежей синтетике.
- Ансамбль корректно находит основные типы ПД в реалистичных текстах.
- Чистый текст без ПД не даёт ложных срабатываний.

### Известные ограничения

Лёгкие n-граммовые модели классифицируют текст целиком, поэтому:
- в очень длинных смешанных списках полей сигнал размывается — часть типов
  может не пересечь порог (используйте `detect_spans` для повышения полноты);
- короткие цифровые/hex-строки могут давать ложные срабатывания у моделей
  с похожими цифровыми паттернами (ИНН/ОМС/военный билет и т.п.).
